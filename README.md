`allgen` is a `go generate` tool that turns a `const` or `var` block into a function
returning all of its members, and writes a test that fails once the block changes and the
function is not regenerated.

## Installation

```bash
go get -tool github.com/vasilesk/allgen/cmd/allgen@latest
```

This adds the command to the `tool` section of `go.mod`, so that `go tool allgen` runs the
version pinned there. The same module provides the package the generated tests import.

## Features

- Works on a block, not on a type: several blocks of one type give separate lists
- Supports `var` blocks: sentinel errors, registries, preset values of any type
- Checks that all members of a block are of the same type
- Writes a test that fails when a member is added, removed or reordered without regeneration
- Keeps the build constraint of the source file in the generated files
- Never overwrites files it did not generate, or files generated for another block
- The package used by the generated tests depends on the standard library only

## Usage

Place the directive right above the block:

```go
package traffic

type Color int

//go:generate go tool allgen
const (
	Red Color = iota
	Yellow
	Green
	colorCount //allgen:skip
)
```

`go generate ./...` writes `all_colors_gen.go`:

```go
// Code generated by allgen; DO NOT EDIT.
// Source: color.go
// Directive: //go:generate go tool allgen

package traffic

// AllColors returns the constants of the block in color.go in declaration order.
// Each call returns a new slice.
func AllColors() []Color {
	return []Color{
		Red,
		Yellow,
		Green,
	}
}
```

and `all_colors_gen_test.go`:

```go
func TestAllColorsUpToDate(t *testing.T) {
	t.Parallel()

	allgen.Check(t, allgen.Block{
		File:      "color.go",
		Directive: "//go:generate go tool allgen",
		Names: []string{
			"Red",
			"Yellow",
			"Green",
		},
	})
}
```

Add `Blue` to the block and forget to run `go generate`, and `go test` reports:

```
all_colors_gen_test.go:16: allgen: generated list is outdated: block in color.go: added Blue; run go generate
```

The [example](./example) directory contains more blocks with their generated files.

### Flags

| Flag | Default | Description |
|---|---|---|
| `-name` | `All<Type>s` | Name of the generated function |
| `-output` | `<name>_gen.go` in snake_case | Name of the generated file |
| `-test` | `true` | Also write `<output>_test.go` checking that the function is up to date |

The default name is `All` followed by the plural of the type name, or `all…` for an
unexported type: `AllColors`, `AllStatuses`, `allCategories`. It is only available when the
members are of a named, non-generic type declared in the same package. Any other type,
such as `error`, `string`, `time.Duration` or `*Config`, requires `-name`:

```go
//go:generate go tool allgen -name AllErrors
var (
	ErrNotFound = errors.New("not found")
	ErrConflict = errors.New("conflict")
)
```

### What makes a block

- The first top-level `const` or `var` declaration below the directive; only comments may
  come between them.
- Members are the declared identifiers in order. Blank identifiers (`_`) and specs marked
  with `//allgen:skip` in their doc or line comment are left out.
- All members must have the same type. Untyped constants such as `const A = 1` are
  rejected, since the list would have no element type.

## Keeping the list up to date

The generated test passes the file, the directive and the member names to `allgen.Check`,
which parses the file, finds the block below the same directive and compares the names.
It compares names only, so updating `allgen` or reformatting the code does not fail it.

- The directive text identifies the block, so it must be unique within its file: two
  blocks need different `-name` values. Editing the directive fails the check until the
  code is regenerated.
- When the source file is not available, as happens when a compiled test binary runs
  elsewhere, the test is skipped rather than failed.
- The check catches changes in blocks that have a generated test. To make sure every
  generated file is current, you may also run `go generate ./... && git diff --exit-code` in CI.

## Limitations

- Blocks in `_test.go` files are not supported.
- A build constraint expressed by the file name (`colors_linux.go`) is not carried over to
  the default output name; pass a matching `-output`, such as `all_colors_gen_linux.go`.
- A file constrained by build tags is generated only when those tags are set, for example
  `GOFLAGS=-tags=integration go generate ./...`.

## Alternatives

Most enum generators also produce a list of values, built from all constants of a type
across the package: [enumer](https://github.com/dmarkham/enumer) (`<Type>Values()`),
[go-enum](https://github.com/abice/go-enum) (`--values`),
[goenums](https://github.com/zarldev/goenums),
[enumall](https://github.com/tomaspavlic/enumall). If you also need `String()`, parsing
and marshaling for constants, they are a better fit. `allgen` covers what they do not:
`var` blocks, several lists per type, and a test guarding the list.
